# Pi 首次使用闭环验证

## 已实现

- 桌面默认打开首次设置；检查依赖、实际 VM/Pi、凭证库、令牌有效期。
- 原生确认后安装 Lima/Python/Codex、创建并部署 Pi、初始化或解锁凭证库、启动 Codex 浏览器登录或导入已有订阅认证。
- 非阻塞安装任务、固定命令白名单、进程组超时、中断记录、失败重试、低磁盘拒绝。设置任务期间禁止并发变更运行环境。
- 首个示例启动新会话，只使用内置虚构计划文本，等待真实独立审批。成功状态须同时匹配会话、任务、文本回复和完成事件；完成记录保存在本机。
- 修正实际示例任务发现的网关工具白名单遗漏：允许 8 个明确工具（新增 host_files），未允许任意工具或远程托管工具。

## 实测

- 新建独立 `secure-vm-onboarding-test`，从 Ubuntu 基础镜像完成 cell、可信服务和固定版本 Pi 安装。
- `python3 scripts/verify-onboarding.py` 通过：新安装状态、随机测试主密钥解锁、合成非真实 token 导入、10 项 cell/Pi 隔离检查、真实 Pi RPC 握手和关闭。没有调用模型或真实账户。
- `python3 scripts/verify-onboarding.py --retry` 通过：重复安装后，合成加密凭证、模型配置、工作区 canary 保留。
- 临时 VM 已删除；现有 secure-vm 已升级并返回 installed/unlocked/configured 全部为 true。
- 桌面首次设置真实状态显示正确，连接 Pi 成功，示例任务成功进入真实策略服务的 PENDING 审批；是否真实模型完成须另记用户审批后的结果，不以握手替代。
- 回归覆盖安装步骤前置条件、失败重试、磁盘不足、互斥、中断恢复、首个任务关联、越权工具拒绝等。最新完整测试为 34 个桌面、6 个 Pi、60 个 Python，共 100 项。

## 仍需用户参与或额外验收

- 用户在系统安装器安装 Homebrew、完成浏览器登录、亲自批准真实模型请求。程序不会替用户接受账户授权或自动批准模型请求。
- 本机已有 Homebrew/Codex，因此未在另一台全新 Mac 上完成系统依赖及浏览器登录实测；全新 Linux VM 安装已实测。
- Developer ID 签名与 Apple 公证仍依赖未提供的证书配置。本次只生成内部开发包，不代表已具备公开分发条件。
